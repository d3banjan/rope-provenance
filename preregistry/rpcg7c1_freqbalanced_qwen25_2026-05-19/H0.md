## 0. Context — the rung-C split

RPCG7a (plain pairs) and RPCG7b (structured pairs) both returned
`NO_GENERALIZATION`, near-identically. Sharpened diagnosis: the `sys`
primitive's gate never learned a list-driven positive open — even in-distribution
`{net,sys}` probes `sys` ≈ 0.02. Two compounding causes: (1) **frequency
imbalance** — `sys` is a *chosen* primitive in only 2 of 5 trained specs (`net`
4, `exec` 3); (2) **DPO is ordinal** — a pair only needs `chosen > rejected`, so
in a multi-permitted spec the model dumps mass on the prior-favoured primitive.

The originally-planned rung C (a cross-spec *consistency* regularizer) is
mistargeted: `sys` is already consistent (consistently ≈ 0.02). Rung C is
therefore **split into two single-lever rungs**:

- **C1 (this rung):** frequency-balanced DPO pairs **only** — no regularizer.
  Tests whether cause (1), the marginal-frequency prior, was the whole story.
- **C2 (only if C1 leaves `sys` weak):** + a within-spec mass-sharing
  regularizer — tests cause (2), the ordinal-DPO weakness.

Single-lever rungs so a positive result is attributable to one cause.

## 1. Obstacle-class pre-flight

**Risked class: NEW** — role-conditioned capability gate; RPCG7 characterises
its compositional generalization.

## 2. Hypothesis

- **H0 (null):** frequency-balancing alone does not yield compositional
  generalization — held-out `auditor`={exec,sys} margin ≤ τ or sign < 3/3.
- **H1 (alternative):** equalising per-primitive chosen-frequency repairs the
  `sys` gate and the held-out specs generalize — `auditor` margin > τ, 3/3 sign.

## 3. Decision rule

`<monorepo>/scripts/decide_perms.py` verdict — **GENERALIZES / GENERALIZES_NOT_LOW_RANK /
NO_GENERALIZATION / VOID** — exactly as RPCG7a/b. On top of the verdict, a
pre-registered diagnostic split using `trained_sys_meanprob` (gated `sys`
open-probability averaged over the trained specs that permit `sys` —
`{net,sys}`, `{exec,net,sys}`) against `trained_sys_open_threshold` = 0.10:

- **GENERALIZES** → frequency was the cause. **Ladder stops** — write up; do NOT
  run C2 (the simpler single-lever fix is the stronger result).
- **NO_GENERALIZATION + `trained_sys_meanprob ≤ 0.10`** → `sys` still does not
  open even in-distribution → **frequency-balancing was not enough** → escalate
  to C2.
- **NO_GENERALIZATION + `trained_sys_meanprob > 0.10`** → `sys` opens
  in-distribution but the held-out specs still fail → the model learned
  **repaired per-primitive priors but not compositional gating** → escalate to
  C2 (the within-spec mass-sharing lever).
- **VOID** → in-distribution gate did not install, or trap did not collapse, or
  DPO did not converge → diagnose before escalating.

Frozen kill criteria (per the methodology directive): if trained `{net,sys}`
still shows `sys ≈ 0.02`, frequency was not enough. If `sys` opens in-dist but
held-out `{sys}`/`{exec,sys}` fail, the model repaired priors not composition.
If C1 succeeds, C2 is NOT run before write-up.

## 5. Null / 6. Trap

Unchanged from RPCG7a/b. Null = balanced-pair DPO (defines τ). Trap = role-swap
DPO; trap in-dist margin must collapse ≤ τ. Frequency-balancing is applied to
all three arms (matched).

## 7. Source / sites — and the rung-C1 recipe deltas

`Qwen/Qwen2.5-0.5B`, bf16, LoRA r=8 q/k/v_proj, β=0.1 + chosen-NLL anchor λ=1.0.
Continued-pretrain reused (rung-independent). Two deltas vs RPCG7a/b, both
recorded:

1. **Frequency-balanced pairs** — chosen/rejected pairs replicated so every
   primitive is a `chosen` primitive equally often (the C1 lever).
2. **Batched DPO** — `BATCH_SIZE` 16, right-padded, per-row last-real-token
   logit; ≈ `STEPS/BATCH_SIZE` optimizer steps, pair-exposures ≈ STEPS (matched
   to RPCG7a/b's 900). RPCG7a/b were batch=1. **Comparability note:** the C1
   lever under test is the *data distribution* (per-primitive frequency);
   batch size is orthogonal optimization. Batching a still-imbalanced recipe
   cannot fix `sys`-underexposure, so a C1 `GENERALIZES` is attributable to the
   frequency-balancing, not the batching.
